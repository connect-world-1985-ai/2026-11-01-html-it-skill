    Findings by severity

    The findings are ordered by severity, so the one that blocks the merge comes first. Use the buttons to show one severity at a time.

    High, blocks merge Refresh token stored in web storage

    F001 refresh token in localStorage. Location: auth/session.ts:88.

    The refresh token is written to localStorage. Every script running on the page can read it, including a script injected through a cross-site scripting bug, so a stolen refresh token would let an attacker keep a user's session alive. The team's rule SEC-12 no tokens in web storage forbids this.

    Expected fix: store the token outside web storage, as SEC-12 no tokens in web storage requires. The review notes do not say which storage to use instead.

    Medium Retry loop has no backoff

    F002 retry loop without backoff. Location: not given in the review summary.

    The retry loop does not wait longer between attempts. When many clients retry like this at the same time, the retries themselves overload the login service. That is how INC-2291 login outage of 14 September 2026 happened: it was caused by retry storms.

    Expected fix: add backoff to the retry loop.

    Low Log line prints the user's email

    F003 log line leaks user email. Location: auth/session.ts:131.

    A log line writes the user's email address, so anyone with access to the logs sees personal data that the log does not need.

    Expected fix: remove the email from the log line.

    Glossary

    localStorage
    Browser storage that keeps data per site and that any script on the page can read; one form of web storage.
    Backoff
    Increasing the wait between retries, typically doubling it each time, so failing clients spread out instead of retrying together.
    Retry storm
    Many clients retrying a failed request at the same moment, so the retries themselves overload the service.
