Usability test prototype

    Password reset prototype

    This is the clickable prototype of the new password reset in the patient portal, for the usability test on Thursday 2026-11-06 date to be confirmed. Testers start on the sign-in screen and click through five steps to a new password; the moderator can reset to the start or jump to any screen, including the expired-link error, from the controls under the prototype.

    Prepared 2026-11-03 for the usability test team. Built for a laptop browser; it opens offline from this file.

    What to try and what is simulated

    Ask testers to reset their password as if they had forgotten it: from Forgot password? on the sign-in screen, through entering an email address and the Check your inbox screen, to setting a new password and returning to sign-in. The moderator can then show the expired-link screen to see whether testers understand how to get a new link.

    This is a prototype. No email is sent, no account is checked and no password is stored. Any email address leads to the Check your inbox screen. The email itself is replaced by two grey prototype buttons on that screen, one for a fresh link and one for a link older than 30 minutes. Signing in with a password does nothing.

    Moderator controls (not part of the product)

    Reset clears every field and the resend timer and returns to the sign-in screen. Each screen also has its own address (for example #expired), so a bookmark opens it directly. For the rule not one of your last 5 passwords, the prototype treats the example password Portal-Example-2025 as one of the last five; type it to show the rule failing.

    Flow and error paths

    The main path has five screens. Two error paths branch off it. An unknown email address does not get its own screen: it leads to the same Check your inbox screen as a known one, so the page never reveals whether an account exists and prevents account enumeration (SEC-31 never reveal whether an account exists). A link older than 30 minutes leads to This link has expired, whose button sends a new link and returns to step 3.

    Rules behind the screens

    ScreenBehaviourWhy
    2 Enter emailAny well-formed email address continues to step 3.The answer must be the same for known and unknown addresses (SEC-31 no account enumeration).
    3 Check your inboxResend is disabled for 60 seconds, then enabled; each resend starts the 60 seconds again.Stops repeated sending while the first email is still on its way.
    4 New passwordAt least 12 characters and not one of the last 5 passwords. Both rules are shown as a checklist that updates while typing; Set new password is enabled only when both are met.Testers see why a password is not accepted before they submit it.
    Link expiredA reset link older than 30 minutes shows This link has expired with a button that sends a new link.Old links in a mailbox cannot be used to take over an account.

    References

    1. SEC-31 The team's security rule "never reveal whether an account exists". For password reset this means an unknown email address gets exactly the same screen as a known one. Source: the prototype brief for the 2026-11-06 usability test; no link to the rule was given.

    Glossary

    Account enumeration
    Finding out which email addresses have an account by watching how a system answers, for example a different message for unknown addresses.
    Moderator
    The person who runs the usability test session, gives testers their task and steers the prototype between tasks.
