    p4m 8.4.0.1 release notes

    p4m product name, not explained in the provided material 8.4.0.1, released on 4 November 2026, is a small update to 8.4.0.0. It stops reminder SMS from being sent twice when an appointment is moved, retries failed reminders automatically, switches booking search to keyset pagination, adds visible labels to the login form and upgrades WildFly to 36.0.1. Before deploying, test paging in booking search and reminders for moved appointments: those are the two changes people will notice, and the commit messages do not say whether any configuration or API change comes with them.

    What changes

    Reminder SMS are no longer sent twice for a moved appointment

    Until now, moving an appointment could cause its reminder SMS to go out twice. 8.4.0.1 fixes this (KT-972 duplicate reminder SMS), so the person receiving reminders gets one message per reminder again. The commit message does not say whether the second message carried the old or the new appointment time.

    Failed reminders are retried automatically

    When sending a reminder fails, p4m now retries it on its own (KT-973 automatic reminder retries). The wording "now automatic" suggests that retries previously needed someone to start them; anyone who did that by hand can stop once 8.4.0.1 is live. The commit message does not state how many retries are made, how far apart they are, or whether this can be configured, so check before relying on it, and watch that the retries do not reintroduce duplicate messages.

    Booking search uses keyset pagination

    Booking search now uses keyset pagination (KT-971 keyset pagination). Instead of skipping a count of rows to reach page five, each page continues after the last result of the previous page. This usually keeps later pages fast on large result sets and stops results from shifting or repeating when bookings are added while someone pages through them. It also tends to change how a client asks for the next page, so clients that request a page by number may need to change; the commit message does not say whether that is the case here.

    The login form has visible labels

    Each field on the login form now has a visible label (KT-975 login form labels), an accessibility improvement. Visible labels help people who use screen readers or zoom, and anyone who has forgotten which field is which once a placeholder disappears. Screenshots of the login screen in user guides may need updating.

    WildFly upgraded to 36.0.1

    p4m now runs on WildFly 36.0.1 (KT-974 WildFly 36.0.1). The commit message does not say which WildFly version it replaces, or whether WildFly is bundled with the release or must be upgraded separately on each server. Operations should confirm this before the deployment window.

    Exception mappers refactored

    The exception mappers were refactored (KT-976 exception mapper refactoring). A refactoring is meant to change the code's structure, not its behaviour. Because exception mappers decide what an error response looks like, clients that read error status codes or error bodies are the ones that would notice an unintended change.

    Before you deploy

    These checks cover the changes that people will notice and the ones the commit messages leave open.

    • Page through a booking search with more than one page of results, forwards and back, and add a booking while paging. No result should repeat or go missing.
    • Check that every client of booking search (web front end, integrations) still gets its next page.
    • Move an appointment that has a pending reminder and confirm that exactly one reminder SMS arrives, with the new time.
    • Make a reminder fail (for example with the SMS gateway unreachable in a test environment) and confirm that it is retried, and sent only once when it succeeds.
    • Open the login form with a screen reader and check that each field is announced with its label.
    • Start p4m on WildFly 36.0.1 in staging and compare a few error responses (not found, validation error, server error) with 8.4.0.0.

    Open questions

    The commit messages do not answer these. The authors of the commits, or whoever owns the release, can.

    • Does keyset pagination change the booking search API, for example from page numbers to a cursor?
    • How many times, and how far apart, are failed reminders retried, and is this configurable?
    • Which WildFly version did 8.4.0.0 use, and does the upgrade need any server-side step?
    • Is the exception mapper refactoring intended to leave every error response unchanged?

    Glossary

    Accessibility (a11y)
    Making software usable for people with disabilities, for example people who use screen readers or keyboard navigation. "a11y" is a common short form: a, eleven letters, y.
    Exception mapper
    In a Jakarta REST (JAX-RS) application, a class that turns a Java exception into an HTTP error response.
    Keyset pagination
    Pagination that continues after the last row seen (for example by start time and ID) instead of skipping a number of rows with OFFSET.
    WildFly
    An open-source Java application server, developed by Red Hat, that runs Jakarta EE applications.
