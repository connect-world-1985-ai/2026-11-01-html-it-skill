    Findings by severity

    Each finding has a number from the reviewer's finding table, its location in the code, what is wrong and why it matters, and a suggested fix. The suggested fixes are the usual way to meet the rule or close the gap; the author may choose another way that does the same.

    High, blocks merge F001 refresh token stored in localStorage

    Location
    auth/session.ts, line 88
    Problem
    The session refresh writes the refresh token to localStorage, a form of web storage. Any script on the page, including one injected through a cross-site scripting bug or a compromised third-party script, can read it and keep a user's session alive from elsewhere.
    Rule
    SEC-12 no tokens in web storage. The reviewer asks for the fix to follow this rule.
    Suggested fix
    Keep the refresh token out of web storage altogether, for example in an HttpOnly cookie set by the server, so that page scripts can no longer read it.

    Medium F002 retry loop without backoff

    Location
    The refresh retry loop in pull request 418 (no line number given in the review)
    Problem
    When a refresh fails, the loop retries straight away, again and again. Many clients doing this at once flood the login service and keep it down. This is the same pattern that caused INC-2291 login outage of 14 September 2026, a retry storm.
    Suggested fix
    Wait longer between attempts, for example with exponential backoff and a cap on the number of retries.

    Low F003 log line leaks user email

    Location
    auth/session.ts, line 131
    Problem
    A log line writes the user's email address. Logs are read by more people and kept longer than user data, so personal data should not appear in them.
    Suggested fix
    Drop the email from the log line, or log an internal user identifier instead.

    Glossary

    Backoff
    Waiting a growing amount of time between retries, usually with some randomness, so that clients do not retry in step.
    HttpOnly cookie
    A cookie the browser sends with requests but that page scripts cannot read.
    Refresh token
    A long-lived credential the app uses to get a new session without asking the user to log in again.
    Retry storm
    A wave of repeated requests from many clients retrying at the same time, which overloads the service they are waiting for.
    Web storage
    Browser storage (localStorage and sessionStorage) that any JavaScript running on the page can read and write.
