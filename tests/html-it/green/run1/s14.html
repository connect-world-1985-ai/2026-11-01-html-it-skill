Bug handoff, 3 November 2026

    Safari 18 users see “Session expired” right after login

    BUG-3188 session expired after login is still open. The most likely cause is that the portal’s session cookie lacks the Partitioned attribute, so Safari drops it after the identity provider sends the user back. A fix exists on a branch but has not been tested: whoever takes over on 4 November 2026 should deploy it to staging and retest with Safari.

    Open Hypothesis not yet tested The previous owner is away from 4 to 6 November 2026.

    Next step

    Deploy branch bugfix/BUG-3188-partitioned-cookie at e19b07f partitioned-cookie fix commit to staging, then repeat the Safari login test described under How to retest. If you do not have staging access yet, it is requested through OPS-77 staging access request.

    Symptom and how to reproduce it

    Right after logging in, some users of the patient portal see “Session expired” and are sent back to the login page. This affects about 2 % of logins since release 8.4.0.0 went out.

    The problem appears only in Safari 18 with Prevent cross-site tracking switched on. Chrome is not affected. On staging, the login fails in about 4 of 10 attempts under those conditions, so a single successful login proves nothing; test several times.

    Current hypothesis

    The portal sets its session cookie with SameSite=None but without the Partitioned attribute. When the identity provider redirects the user back to the portal, Safari’s tracking protection treats that cookie as cross-site and drops it. The portal’s next request then arrives without a session, and the portal reports the session as expired.

    The terminal log supports this picture: every failure shows the same pair of messages, a warning that /portal/home received no session cookie from Safari/18.1, immediately followed by a redirect to /login?expired=1. The full excerpt is in the appendix.

    Already ruled out

    Three other explanations were checked and excluded, so there is no need to repeat them:

    • Server clock skew. NTP was checked on all nodes; the clocks agree.
    • Token lifetime. The token lifetime has not changed since release 8.3.
    • Load balancer stickiness. The error also occurs with a single node, so routing between nodes is not the cause.

    Glossary

    Identity provider
    The separate login service that checks the user’s credentials and then redirects back to the portal.
    Load balancer stickiness
    The load balancer sending all requests of one user to the same server node.
    NTP
    Network Time Protocol: keeps server clocks synchronised.
    Partitioned
    A cookie attribute that stores the cookie separately for each top-level site, so privacy-focused browsers keep it in cross-site contexts instead of dropping it.
    Prevent cross-site tracking
    A Safari privacy setting that blocks or isolates cookies set in a cross-site context.
    SameSite=None
    A cookie setting that allows the browser to send the cookie on cross-site requests; it must be combined with Secure.
