    Safari "Session expired" after login

    BUG-3188 "Session expired" right after login is still open, and a fix is ready to test. The most likely cause is that Safari 18, with "Prevent cross-site tracking" on, drops the portal's session cookie after the redirect back from the identity provider, because the cookie has no Partitioned attribute. The next step is to deploy the fix candidate, e19b07f partitioned session cookie, to staging and retest with Safari.

    Open Fix not yet tested

    Handoff written on 3 November 2026 for the engineer who takes over the bug while its author is out from 4 to 6 November 2026. The note says "tomorrow"; read here as 4 November 2026 (to be confirmed).

    Symptom and how to reproduce it

    Some users of the patient portal see "Session expired" immediately after they log in. It affects about 2 % of logins since release 8.4.0.0; the note does not give the rate before that release.

    The problem appears only in Safari 18 with the privacy setting Prevent cross-site tracking turned on. Chrome is not affected. On staging it reproduces in 4 of 10 login attempts, so a single successful login proves nothing: always count over several attempts.

    Current hypothesis

    The session cookie is set with SameSite=None but without the Partitioned attribute. After the identity provider redirects the browser back to the portal, Safari with tracking prevention discards that cookie. The portal then sees a request without a session and treats it as an expired session. This is still a hypothesis; the retest on staging confirms or rejects it.

    The log supports the lower half of the chain. Between 16:41 and 16:44 UTC on 3 November 2026, every request from Safari/18.1 logged the warning SessionFilter - no session cookie on /portal/home, followed by the redirect AuthRedirect - redirect to /login?expired=1. The log cannot show why the cookie is missing; that is the part the retest checks.

    Glossary

    Clock skew
    Server clocks that disagree, so a token can look expired on one node while it is still valid on another.
    Identity provider
    The service that checks the user's credentials and sends the browser back to the portal with the login result.
    Load balancer stickiness
    A load balancer setting that keeps sending one user to the same server node.
    NTP
    Network Time Protocol: keeps server clocks synchronised.
    Partitioned
    Cookie attribute that asks the browser to keep the cookie in a separate store per top-level site. Browsers that block cross-site cookies may still accept a partitioned one; whether Safari 18 does so in this case is what the retest checks.
    Prevent cross-site tracking
    A Safari privacy setting that blocks or limits cookies used across different sites.
    SameSite=None
    Cookie attribute that lets the browser send the cookie on cross-site requests, such as the redirect back from an identity provider.
    Staging
    The pre-production environment where changes are deployed and tested before release.
