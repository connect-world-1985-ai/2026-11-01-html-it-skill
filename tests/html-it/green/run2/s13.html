p4m release notes

    p4m 8.4.0.1

    p4m 8.4.0.1, released on Wednesday 4 November 2026, is a small maintenance release. Moving an appointment no longer sends the same reminder SMS twice, failed reminders are now retried automatically, and the login form gets visible field labels. Under the hood, booking search switches to keyset pagination and the application server is upgraded to WildFly 36.0.1. Nobody has to change how they use p4m; whoever deploys it should check the release against WildFly 36.0.1 first (see Before you deploy).

    Release 8.4.0.1 follows 8.4.0.0. Six changes. Source: the commit messages between the two releases; nothing beyond those messages was available, so details that the messages do not give are marked to be confirmed. Prepared 2026-11-03.

    Changes users notice

    Reminder SMS sent only once after a move Fix

    In 8.4.0.0, moving an appointment to a new time sent the reminder SMS twice. From 8.4.0.1 the reminder goes out once, so the person with the appointment is no longer confused by two identical messages. The commit message does not say whether every kind of move was affected or only some to be confirmed. Ticket: KT-972 duplicate reminder SMS.

    Reminder retries happen automatically Improvement

    When sending a reminder fails, p4m now retries it on its own. Before this release, retries were not automatic, so anyone who currently retries failed reminders by hand should no longer need to. The commit message does not say how many times p4m retries, how long it waits between attempts, or what happens when every attempt fails; ask the owner of KT-973 automatic reminder retries before telling practices what to expect to be confirmed.

    Visible labels on the login form Accessibility

    The login form now shows a visible label for each field. Visible labels help people who use screen readers or magnification, and anyone who forgets what a field was for once they start typing; this is an accessibility improvement. Users may notice that the form looks slightly different. Ticket: KT-975 login form labels.

    Platform and internal changes

    Booking search pages with keyset pagination Improvement

    Booking search now uses keyset pagination. Instead of telling the database to skip a number of rows for each new page, the search continues after the last result shown. This approach usually keeps later pages fast and stops results from shifting between pages when bookings are added while someone is paging. The commit message gives no measurements and does not say whether the visible sort order or the way pages are reached (for example jumping to a page number) changed to be confirmed. Ticket: KT-971 keyset pagination.

    WildFly upgraded to 36.0.1 Platform

    p4m runs on WildFly, and this release moves it to version 36.0.1. The previous WildFly version is not named in the commit message. A server upgrade can change configuration defaults, so it is the one change in this release that needs attention at deployment time. Ticket: KT-974 WildFly 36.0.1.

    Error mapping code restructured Internal

    The code that turns server errors into responses (the ExceptionMappers) was refactored. A refactor is not meant to change behaviour, but because this code shapes every error response, error messages and status codes are worth a quick look in testing. The commit message does not describe the new structure. Ticket: KT-976 ExceptionMapper refactor.

    Before you deploy

    These checks follow from the changes above. They are suggestions for whoever deploys 8.4.0.1, not steps taken from an existing runbook.

    • Confirm that the environment's WildFly configuration works with 36.0.1 (KT-974 WildFly 36.0.1).
    • Move a test appointment and check that exactly one reminder SMS is sent (KT-972 duplicate reminder SMS).
    • Page through a booking search with more than one page of results (KT-971 keyset pagination).
    • Trigger a few error responses and compare them with 8.4.0.0 (KT-976 ExceptionMapper refactor).

    Open questions. The commit messages leave four things open: the retry rules for reminders, any visible change to booking search paging, the WildFly version this release upgrades from, and whether the release needs any configuration change. The ticket owners can answer them; the team's ticket tracker is not linked from this page because its address was not provided.

    Glossary

    Accessibility (a11y)
    Making software usable by people with disabilities. "a11y" is shorthand: an "a", eleven letters, a "y".
    ExceptionMapper
    A Java class that converts an exception thrown in the server into an HTTP response, such as an error status and message.
    Keyset pagination
    Pagination that continues after the last row seen (for example by start time and ID) instead of skipping a row count with OFFSET.
    Refactor
    Restructuring code without intending to change what it does.
    WildFly
    An open-source Java application server; p4m is deployed on it.
