Appointment reminders: move them to a queue

We recommend option B: send appointment reminders through a RabbitMQ queue instead of the nightly cron job. It is the only option that makes retries automatic and removes the 02:00 load peak while keeping patient data in our own hosting. It costs 2 sprints of work.

Decision needed from Lena (tech lead) at this review. If B is chosen, work starts in sprint 47.

Option B in one picture

The core service hands each reminder to a queue; a sender works through it at its own pace

Today one batch does all the work at 02:00. With a queue, the core service only records that a reminder is due; the sender delivers reminders as fast as it safely can, and a failed reminder is retried by the queue instead of by a person.

Stress that RabbitMQ is not new to us: sms-service already uses it. The new operational work is the runbook.

Glossary

Back-pressure
A way for a slow consumer to limit how fast work reaches it, so a burst waits in the queue instead of overloading the system.
Cron job
A job that the server starts automatically on a fixed schedule; here the nightly reminder batch in the core service.
Data processing agreement
A contract that sets out how an outside company may process personal data on our behalf.
RabbitMQ
A message broker: programs put messages into a queue and other programs take them out and process them. sms-service already uses it.
Runbook
A written guide for operations staff: how to run, monitor and repair a system.
