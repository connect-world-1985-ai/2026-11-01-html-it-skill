    Symptom and reproduction

    After logging in to the patient portal, some users immediately see "Session expired" and are sent back to the login page. This affects about 2 % of logins since release 8.4.0.0.

    It happens only in Safari 18 with the privacy setting "Prevent cross-site tracking" switched on. Chrome is not affected. On staging it reproduces in 4 of 10 attempts, so a single successful login proves nothing; test several times.

    Already ruled out

    Suspected causeWhy it is ruled out
    Server clock skewNTP (network time protocol) synchronisation was checked on all nodes.
    Token lifetimeUnchanged since release 8.3.
    Load balancer stickinessThe error also occurs with a single node.

    Current hypothesis

    The session cookie is set with SameSite=None but without the Partitioned attribute. Login goes through a redirect to the identity provider and back. The suspicion is that Safari, with tracking protection on, drops the cookie after that redirect, so the portal's next request carries no session and is treated as expired. That fits the log: the failures shown are "no session cookie on /portal/home" from Safari 18.1, each followed by a redirect to /login?expired=1.

    Glossary

    Clock skew
    A difference between the clocks of two machines, which can make a still-valid token look expired.
    Identity provider
    The external service that checks the user's credentials and then redirects back to the portal.
    Load balancer stickiness
    Routing all requests of one user to the same server node, so a session stored on that node is found again.
    Partitioned
    A cookie attribute that stores the cookie separately per top-level site; browsers with strict tracking protection accept such cookies in cross-site contexts where they drop ordinary ones.
    Prevent cross-site tracking
    A Safari privacy setting that blocks or restricts cookies set in a cross-site context, for example during a redirect from another domain.
    SameSite=None
    A cookie setting that allows the browser to send the cookie on cross-site requests; browsers require such a cookie to be Secure.
