    Add the html-it skill, its tests, the verdict page and four samples

    This change adds html-it, an agent skill that turns whatever is in the conversation into one self-contained HTML file a colleague can open offline. It also adds the tests that prove the skill changes agent behaviour, a research verdict on when one file is enough, and four sample pages in different forms.

    Summary

    • The skill (skills/html-it/): a short orchestrator, seven reference files, one HTML shell with three themes, and a standard-library Python checker. It works in any agent that reads skill folders D1 portable folder.
    • The tests (tests/html-it/): sixteen pressure scenarios with fixtures, a baseline run without the skill, four runs with it, and unit tests for the checker.
    • The verdict page (research/single-html-verdict.html): which content fits one HTML file and where it stops, with numbers.
    • Four samples (samples/): this write-up, a Chinese explainer, a theme sketch board and a keyboard deck.
    • README: rewritten around the skill, with verified install folders for Claude Code, Codex and Cursor.

    Why

    Agents already write good design notes, pull request write-ups and reviews, but as Markdown in a chat. Colleagues who were not in that chat get bare ticket numbers, unexplained terms and a wall of text. The team's research (research/report.md) compared ten ways to produce shareable HTML and recommended a skill that chooses the page's shape from the content.

    Three choices shape this change:

    • Zero network requests when the page opens D3 fully offline. Common CDNs are blocked or unreliable for the team in China, and third-party scripts next to internal content are a risk.
    • Form from content traits, not a fixed template list D9 composed form. A review, a deck and a sketch board come out of the same rules.
    • No bare references D11 ref chips. Every ticket or pull request number links to an entry that says what it is, and the checker fails the page otherwise.

    Key files, annotated

    1. SKILL.md: the trigger

    The description lists situations only, never the steps, so the agent reads the whole skill instead of following a summary.

    ---
name: html-it
description: Use when content in the conversation should be shared with
  teammates or kept for later reading as a web page instead of Markdown -
  pull request write-ups, code reviews, design proposals, plans, explainers,
  … or "make this readable for the team".
---

**Core principle: the reader was not here.** Every sentence, number and ID
must make sense to someone opening the file cold months later.

    Look at: the gate list further down. Gate 1, the plan card, is always asked D5 adaptive gates; four more appear only when their condition holds, and language is part of Gate 1 every time D6 language asked.

    2. scripts/check_html.py: references must resolve

    Anything that looks like an ID in visible text must be a chip with a References entry. Code, styles and scripts are skipped.

    Look at: _network_failures, which fails any remote src, href, CSS url(), @import or script load such as fetch("https://…"). Plain links to other sites stay allowed, because they are navigation, not loading.

    3. assets/shell.html: one identity, three variants

    Every colour is a token on :root; each variant redefines the tokens for light and dark, and an explicit toggle wins both ways D4 house theme.

    :root {
  --bg: #FAF9F5; --surface: #FFFFFF; --fg: #141413;
  --accent: #D97757; --accent-ink: #A9502F; …
}
:root[data-variant="graphite"] { /* neutral engineering */ … }
@media (prefers-color-scheme: dark) {
  :root[data-variant="graphite"]:not([data-theme="light"]) { … }
}

    Look at: the font stacks. They are system fonts with Chinese fallbacks, so nothing is downloaded and Chinese text renders on Windows, macOS and Linux.

    How to review

    1. Read skills/html-it/SKILL.md start to finish (about seven minutes). Check that the steps and gates match the decisions below D8 architecture.
    2. Skim references/forms.md and references/cross-references.md; they carry most of the judgement.
    3. Run the two commands above. Both should print PASS and OK.
    4. Open three outputs side by side: tests/html-it/green/s1.html (code review), s2.html (design proposal) and s9.html. Compare one with its baseline in tests/html-it/baseline/.
    5. Open the four samples and the verdict page. Toggle the theme, narrow the window, and press the arrow keys in the deck.
    6. Check that nothing under references/ or research/evidence/ changed: git status -- references research/evidence prints nothing.

    References

    The twelve decisions below come from Section 0.2, "Confirmed decisions", of the plan docs/plans/2026-11-03-html-it-skill.md. They were settled before work started.

    1. D1 Agent-agnostic portable skill folder: SKILL.md plus references, assets and scripts, so it runs in Claude Code, Codex, Cursor and others.
    2. D2 Full HTML feature set; JavaScript is always allowed. No sanitised chat-paste mode.
    3. D3 Fully offline at read time: zero network requests when the page opens. Prefer drawn SVG and pre-rendered highlighting; inline a pinned library at build time when one is truly needed.
    4. D4 House theme plus variants: Ivory by default, Graphite for engineering, Console for dense dashboards, each in light and dark.
    5. D5 Adaptive gates: the plan card is always asked, further gates only when their condition holds, using the environment's own question tool when there is one.
    6. D6 Language is asked every time: English (default), Deutsch or Chinese.
    7. D7 Image generation is optional: only with an available tool and only when an image adds meaning; never for diagrams, charts or UI text; never block without a tool.
    8. D8 Architecture: one orchestrator, a reference kit, a shell template and a checker, under the name html-it. A router with specialist skills and one huge SKILL.md were rejected.
    9. D9 Form is composed from content traits; the forms catalogue holds worked examples, not templates.
    10. D10 Single file by default; a multi-part folder only past about 20 MB or when assets must stay separately editable. Shared state and live data are out of scope, and the page says so.
    11. D11 No bare references: every opaque ID becomes a ref chip to a References entry or is visibly marked unresolved; jargon is defined at first use.
    12. D12 Out of scope: hosting and publishing, a Teams paste-safe mode, React or bundler pipelines as the default, and committing without the author's explicit yes.

    Glossary

    Gate
    A question the skill asks before building. The plan card (form, theme, language, depth) is always asked; the others only when needed.
    Ref chip
    An ID shown as a small link that opens a short explanation and jumps to its References entry.
    Pressure scenario
    A realistic task, given to a fresh agent, that tempts it to cut corners. Run once without the skill and again with it.
    Rubric
    The eleven pass or fail checks each output is scored on, from "opens offline" to "asks only the gates the case needs".
